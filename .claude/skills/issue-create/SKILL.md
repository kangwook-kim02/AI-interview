# issue-create — 이슈 생성 스킬

## 목적
막연한 작업을 **작게 스코프된 이슈**로 변환한다. 한 이슈 = **하나의 머지 가능한 변경**(보통 반나절~하루).

## 절차

1. **입력 파악**: 사용자가 준 작업 설명, 또는 `docs/BACKLOG.md`의 항목(번호/제목)을 읽는다.
2. **스코프 점검 — 너무 크면 쪼갠다.**
   - 한 PR에 리뷰 가능한 크기인가? 아니면 2개 이상 이슈로 분리 제안.
   - "완료"를 체크 가능한 문장으로 쓸 수 있는가? 없으면 범위가 모호한 것.
3. **의존성 파악**: 먼저 끝나야 할 이슈가 있는지 `docs/BACKLOG.md`/기존 이슈에서 확인해 명시.
4. **템플릿 채우기**: `.github/ISSUE_TEMPLATE/task.md`의 모든 섹션을 구체적으로 작성.
   - 제목: `[영역] 한 줄` (영역 예: 스캐폴딩/인증/자소서/면접/디자인/인프라)
   - 관련 FR 번호(PRD) 있으면 목적에 링크.
   - "범위 밖"을 반드시 적어 스코프 비대화를 막는다.
5. **생성**:
   - `gh` 있으면: `gh issue create --title "..." --body "..." --label task` 로 올리고 **이슈 URL/번호를 보고**한다.
   - `gh` 없으면: 완성된 이슈 마크다운을 출력하고 "GitHub에 수동으로 붙여넣으세요" 안내(+ `docs/SETUP.md`의 gh 설치 항목 안내).
6. 여러 개를 한 번에 요청받으면 **의존성 순서대로** 생성하고, 각 이슈 본문의 "의존성"에 앞 이슈 번호를 채운다.

## 원칙
- 작게. 애매하면 더 쪼갠다.
- 완료 조건은 **검증 가능**하게(“로그인 되면 끝” ❌ → “이메일+비번으로 가입→로그인→보호 페이지 접근 가능, 로그아웃 시 차단” ✅).
- 구현 지시는 넣지 않는다(그건 issue-work가 함). 이슈는 **무엇/왜/완료조건**까지만.
