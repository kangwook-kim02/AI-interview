## 1. 개요 (Overview)

### 1.1 한 줄 요약
사용자가 자신의 자기소개서를 등록하면, AI가 자소서를 분석해 **실시간 음성 면접**을 진행하고(질문 TTS → 음성 답변 녹음 → 꼬리질문), 면접 과정을 **카메라/음성으로 녹화**하는 웹 서비스.

### 1.2 문제 정의
- 취업 준비생은 실제 면접과 유사한 환경에서 반복 연습할 기회가 부족하다.
- 기존 모의면접은 질문이 정형화되어 있어, **본인 자소서 기반의 맞춤 질문**과 **실시간 꼬리질문**을 받기 어렵다.

### 1.3 목표 (MVP Goals)
1. 사용자가 회사별 자기소개서를 등록/관리할 수 있다.
2. 등록된 자소서 기반으로 AI가 질문을 생성하고 **음성으로** 면접을 진행한다.
3. 면접 전 과정을 카메라/음성으로 녹화하고, 진행 상황·시간을 실시간 표시한다.

### 1.4 비목표 (Non-Goals, MVP 제외)
- 면접 결과에 대한 상세 점수/피드백 리포트 (2차)
- 녹화 영상 재생/다운로드/공유 (2차, 저장만 MVP)
- 다국어 지원 (MVP는 한국어 고정)
- 모바일 네이티브 앱 (MVP는 데스크톱 브라우저 우선)
- 결제/구독

## 3. 핵심 사용자 흐름 (User Flow)

```
[회원가입/로그인]
      │
      ▼
[대시보드: 내 자기소개서 카드 목록]
      │  (+ 새 자소서 등록)
      ▼
[회사 정보 입력 페이지]
   - 회사 이름
   - 지원 직무
   - 자소서 문항(질문 + 답변) N개  (행 추가/삭제)
   - 경험 입력 N개                 (행 추가/삭제)
      │  (업로드/저장)
      ▼
[대시보드로 복귀 → 새 카드 생성됨]
      │  (카드의 "면접 보기" 버튼 클릭)
      ▼
[면접 준비: 카메라/마이크 권한 요청 + 장비 점검]
      │  (면접 시작)
      ▼
[면접 진행 페이지]  ←──────────────┐
   1. AI 질문 TTS 재생              │
   2. TTS 종료 → 자동 녹음 시작     │  (꼬리질문 루프, 최대 2회)
   3. 사용자 "대답 완료" → 녹음 종료 │
   4. STT로 답변 텍스트화           │
   5. AI가 꼬리질문 여부 판단 ──────┘
      │  (메인 4문항 + 꼬리질문 소진)
      ▼
[면접 종료 → 요약/완료 화면]
```

## 4. 기능 요구사항 (Functional Requirements)

요구사항 ID 규칙: `FR-<영역>-<번호>`

### 4.1 인증 (FR-AUTH)
- **FR-AUTH-1** 이메일+비밀번호로 회원가입할 수 있다.
- **FR-AUTH-2** 이메일+비밀번호로 로그인/로그아웃할 수 있다.
- **FR-AUTH-3** 로그인하지 않은 사용자는 대시보드/자소서/면접 페이지에 접근할 수 없다(보호 라우트).
- **FR-AUTH-4** 모든 데이터는 로그인 계정에 귀속된다(사용자는 본인 데이터만 조회/수정).
- (선택) FR-AUTH-5 소셜 로그인(Google) — Supabase 기본 제공, 후순위.

### 4.2 자기소개서 관리 (FR-CL)
- **FR-CL-1** 사용자는 새 자소서(=회사 지원 카드)를 생성할 수 있다.
- **FR-CL-2** 회사 이름을 입력한다. (필수)
- **FR-CL-2b** 지원 직무를 입력한다. (필수) — 질문 생성 시 직무 맥락에 활용.
- **FR-CL-3** 자소서 문항을 추가할 수 있다. 각 문항 = {질문, 답변}. 최소 1개 필요.
- **FR-CL-4** 자소서 문항은 동적으로 추가/삭제/재정렬할 수 있다.
- **FR-CL-5** 경험 항목을 추가할 수 있다. 각 경험 = {내용(자유서술)}. 0개 이상.
- **FR-CL-6** 경험 항목도 동적으로 추가/삭제할 수 있다.
- **FR-CL-7** 저장 시 대시보드에 "자기소개서 카드"로 표시된다. (회사명, 직무, 문항 수, 생성일)
- **FR-CL-8** 카드를 수정/삭제할 수 있다.
- **FR-CL-9** 각 카드에는 "면접 보기" 버튼이 있다.

### 4.3 면접 준비 (FR-PREP)
- **FR-PREP-1** 면접 시작 전 카메라/마이크 권한을 요청한다.
- **FR-PREP-2** 권한 거부 시 안내 메시지와 재시도 방법을 표시한다.
- **FR-PREP-3** 브라우저가 Web Speech API(TTS/STT)를 지원하지 않으면 경고를 표시한다.

### 4.4 면접 진행 (FR-INT)
- **FR-INT-1** 면접 시작 시 AI가 자소서(문항+답변+경험)를 분석해 **메인 질문 4개**를 생성한다.
- **FR-INT-2** 각 질문은 TTS로 음성 재생된다.
- **FR-INT-3** TTS 재생이 끝나면 **자동으로** 음성 녹음이 시작된다(별도 시작 버튼 없음).
- **FR-INT-4** 사용자가 "대답 완료" 버튼을 누르면 녹음이 종료된다.
- **FR-INT-5** 종료된 답변은 STT로 텍스트화된다.
- **FR-INT-6** AI는 답변을 바탕으로 꼬리질문 여부를 판단하며, **질문당 최대 2개**의 꼬리질문을 할 수 있다.
- **FR-INT-7** 꼬리질문도 TTS→자동녹음→대답완료→STT의 동일 사이클을 따른다.
- **FR-INT-8** 화면 좌측에 사용자 카메라 영상, 우측에 AI 질문/답변 내용이 실시간 표시된다.
- **FR-INT-9** 상단에 메인 질문 진행률(예: 2/4)을 표시한다.
- **FR-INT-10** 전체 면접 경과 시간을 실시간(mm:ss) 표시한다.
- **FR-INT-11** 면접 전체 과정(카메라+마이크)이 녹화되어 Storage에 저장된다.
- **FR-INT-12** 모든 메인 질문과 꼬리질문이 끝나면 면접이 자동 종료된다.
- **FR-INT-13** 사용자는 중도에 면접을 종료할 수 있다.

### 4.5 면접 기록 (FR-REC)
- **FR-REC-1** 면접 종료 시 메타데이터(소요시간, 질문/답변 전사, 녹화 파일 경로)를 저장한다.
- **FR-REC-2** (MVP 범위 내 최소) 완료 화면에서 해당 면접의 Q&A 전사 요약을 볼 수 있다.

## 5. 비기능 요구사항 (Non-Functional)

- **NFR-보안**: 모든 사용자 데이터는 Supabase RLS(Row Level Security)로 계정 단위 격리. 저장소(녹화 파일)도 사용자별 경로 + 접근 정책.
- **NFR-성능**: 질문 생성 지연은 로딩 인디케이터로 흡수. TTS는 질문 수신 즉시 재생.
- **NFR-프라이버시**: 카메라/마이크 녹화는 명시적 동의 후에만. 녹화물은 본인만 접근.
- **NFR-브라우저**: Chrome(데스크톱) 최신 2버전 우선 지원. Web Speech API 의존.
- **NFR-확장성**: TTS/STT/LLM은 **교체 가능한 어댑터**로 추상화(아래 ARCHITECTURE 참조).
- **NFR-비용**: MVP는 브라우저 내장 음성(무료) + Claude API 과금만.

## 6. 주요 리스크 & 결정 (Risks & Decisions)

| 항목 | 리스크 | MVP 결정 |
|---|---|---|
| 브라우저 STT 정확도 | Web Speech STT는 한국어 정확도/안정성 편차 | MVP는 Web Speech로 시작, 어댑터로 추상화해 추후 Whisper 등 교체 가능 |
| TTS 종료 감지 | `onend` 이벤트 신뢰성 | 상태머신에서 fallback 타이머 병행 |
| 녹화 용량 | 긴 면접 영상 용량 | MediaRecorder + 적절한 코덱/비트레이트, 종료 시 1회 업로드 |
| 꼬리질문 판단 품질 | LLM이 과도/부족하게 꼬리질문 | 명시적 프롬프트 + 최대 2개 하드 캡 |
| 동시 녹화+STT | 하나의 마이크 스트림 공유 | MediaRecorder(저장용)와 SpeechRecognition(전사용) 분리 운용, 설계에서 검증 |

## 7. 오픈 퀘스천 (Open Questions) — 함께 확정 필요

1. **꼬리질문 타이밍**: 각 메인 질문 직후 꼬리질문을 할지, 아니면 메인 4개를 먼저 다 받고 나서 할지? → *제안: 메인 질문 직후 꼬리질문(자연스러운 대화 흐름).*
2. **STT 실시간 표시**: 답변 중 실시간 자막처럼 보여줄지, 완료 후 한 번에 보여줄지? → *제안: 실시간 interim 표시 + 완료 시 확정.*
3. **녹화 저장 필수 여부**: STT 전사만으로 충분한지, 영상도 반드시 저장할지? (용량/비용 영향) → *제안: MVP는 영상 저장하되 재생 UI는 2차.*
4. **질문 언어/난이도**: 압박 면접 톤 vs 편안한 톤? → *제안: 중립적/표준 면접관 톤.*
5. **면접 재시도**: 같은 자소서로 여러 번 면접 가능한지(기록 누적)? → *제안: 가능, 면접 기록 누적.*

## 8. 수용 기준 (MVP Acceptance Criteria)

- [ ] 신규 사용자가 가입 → 로그인 → 자소서 등록 → 면접 완료까지 **중단 없이** 수행 가능.
- [ ] 면접 중 질문이 음성으로 나오고, TTS 종료 후 자동 녹음되며, "대답 완료"로 종료된다.
- [ ] 메인 4문항 + 문항별 최대 2 꼬리질문이 상한 내에서 동작한다.
- [ ] 진행률(n/4)과 경과 시간이 실시간 갱신된다.
- [ ] 좌측 카메라 / 우측 Q&A가 동시에 보인다.
- [ ] 면접 종료 후 전사 기록과 소요시간이 DB에 저장된다.
- [ ] 로그아웃 상태에서 보호 페이지 접근이 차단된다.

## 9. 마일스톤 (제안)

| 단계 | 내용 |
|---|---|
| M0 | 문서 확정 (PRD + ARCHITECTURE) ← **현재** |
| M1 | 프로젝트 스캐폴딩 + Supabase 연동 + 인증 |
| M2 | 자소서 CRUD (회사 정보 입력/카드 목록) |
| M3 | 면접 준비(장비 점검) + 질문 생성(Claude) API |
| M4 | 면접 진행 상태머신 (TTS→녹음→STT→꼬리질문) |
| M5 | 녹화(MediaRecorder) + Storage 업로드 + 기록 저장 |
| M6 | 통합 테스트 + 폴리싱 |
