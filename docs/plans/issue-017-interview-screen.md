# Plan — Issue #17: 음성 면접 진행 화면 연결

## 목표

준비 화면에서 실제 면접으로 이어지고 카메라, 현재 질문, 답변 초안과 확정 기록,
메인 질문 진행률 및 경과 시간을 보여준다. 기존 상태머신으로 음성 진행·재시도·종료를 제어한다.

## 단계별 계획

1. 인증·소유권 검증을 거치는 질문 UUID 조회 API를 추가한다. 기존 시작·꼬리질문 계약은 유지한다.
2. HTTP 세션 IO에서 메인/꼬리 위치를 저장된 UUID로 변환하고 기존 API에 확정 답변을 전달한다.
3. 영상 전용 카메라 포트를 추가한다. 취소·연결 해제·늦게 도착하는 권한 응답을 정리한다.
4. 준비 화면에서 장비를 정리하고 진행 화면으로 이동한다. 카메라 준비 후 생성 요청을 시작한다.
5. 데스크톱 2열/모바일 세로 화면에 진행률·시간·질문·초안·확정 기록을 표시한다.
6. 상태별 조작, 재시도, 중도 종료 확인과 자연 종료를 연결하고 모든 자원을 정리한다.
7. 연결 경계 테스트와 브라우저 화면 확인 후 reviewer의 필수 지적을 반영한다.

- docs: 이 계획, `docs/API.md`, `docs/SETUP.md`

## 외부 의존·어댑터 / 스키마 변경

기존 TTS/STT 팩토리와 상태머신·세션 controller를 재사용한다. 영상 전용 카메라는
`lib/devices` 포트로 제공한다. DB 조회는 Supabase 서버 어댑터를 통한다.
LLM provider·DB 스키마 변경은 없다. 최종 DB 종료 저장·결과 화면·영상 녹화는 범위 밖이다.

## 리스크 · 열린 질문 · 승인 필요 지점

- Strict Mode·중복 클릭으로 시작 API가 중복 호출되지 않아야 한다.
- 꼬리 순서는 세션에서 1..2, DB에서 0..1이며 항상 메인 UUID를 부모로 사용한다.
- 초안·오류의 부분 전사는 확정 답변과 구별한다. 평가 재시도는 같은 확정 답변을 전송한다.
- `finishing`은 즉시 `done`이 될 수 있다. 두 단계와 SPA 이탈·pagehide 모두 정리한다.
- 커밋·푸시·PR은 구현·검증·리뷰가 끝난 구체적인 결과에 대해 사용자 승인 후 진행한다.
  승인 시 계획 파일을 첫 커밋으로 분리한다.

## 검증 계획

질문 조회 인증·소유권·오류, 위치→UUID 매핑, HTTP 오류·취소, 카메라 정리를 테스트한다.
lint/typecheck/test/build를 실행한다. 브라우저에서 데스크톱·모바일 레이아웃, 생성 로딩,
TTS→STT, 초안/확정, 재시도, 종료 확인·자연 종료와 이탈 정리를 확인한다.
실제 물리 장비·외부 AI를 사용하지 않은 검증은 그 한계를 보고한다.
