- 상태: 구현중

## 목표

본인 지원 카드의 면접 준비 화면에서 명시적으로 동의한 뒤 카메라·마이크를 점검한다.
카메라 영상, 실제 마이크 입력, TTS·STT 지원을 모두 확인해야 준비 완료 동선을 진행할 수 있다.
취소·이탈 시 장비 자원을 해제하고 녹화·업로드·질문 생성은 수행하지 않는다.

## 단계별 계획

1. 인증, UUID 검증, 서버 소유권 확인이 있는 준비 데이터 조회를 구현한다.
2. 브라우저 API를 lib 포트 뒤로 감추고 지원 확인·스트림 획득·마이크 레벨 분석·정리를 제공한다.
3. 동의 전 권한 요청을 막고 카메라 영상 준비와 실제 마이크 입력을 각각 확인한다.
4. 재시도·동의 철회·취소·unmount·pagehide 시 정리하고 늦게 반환된 스트림도 중단한다.
5. 한국어 오류·해결 안내, 브라우저 지원 안내, 필수 조건에 따른 완료 버튼을 구현한다.
6. 자동 검증 및 reviewer 리뷰를 진행하고 지적을 반영한다.

- `src/features/interview/components/{InterviewPreparation,DeviceCheck}.tsx` — 서버/클라이언트 화면

- `src/config/interview.ts` — 입력 감지 정책 상수

## 외부 의존·어댑터 / 스키마 변경

기존 Supabase 사용자 세션 및 소유권 검증이 있는 findCoverLetter를 재사용한다.
브라우저 캡처·Web Audio·음성 API 지원 탐지는 장비 점검 포트 뒤에 둔다.
실제 TTS/STT 실행은 없으며 패키지·환경 변수·DB 스키마 변경도 없다.

## 리스크 · 열린 질문 · 승인 필요 지점

- 질문 생성·진행 라우트 연결은 범위 밖이다. CTA는 “점검 마치기”로 두고 로컬 완료 안내 후 장비를 해제한다.
- API 존재 여부는 실제 음성 서비스 동작을 보장하지 않는다.
- 권한 요청을 직접 취소할 수 없으므로 세대 번호로 늦은 결과를 정리한다.
- AudioContext는 사용자 클릭에서 활성화하고 스피커에 연결하지 않는다.
- 커밋·푸시·PR 생성은 구현·검증·리뷰 결과와 PR 초안을 준비한 뒤 최종 승인받는다.
  승인 후 플랜을 브랜치 첫 커밋으로 포함한다.

## 검증 계획

- lint, typecheck, test, build.
- 인증 없음, 잘못된 ID, 타인/없는 카드, 정상 카드, 조회 실패를 mock으로 검증한다.
- 음성 지원 조합·권한 오류·자원 정리·요청 취소 후 늦은 스트림 반환을 검증한다.
- 가능하면 브라우저에서 동의 전 미요청, 입력 감지, CTA 차단, 취소 및 레이아웃을 확인한다.
- 실제 하드웨어 및 권한 동작 미검증 범위는 보고한다.

## (구현 후) 변경 메모 / 리뷰 반영

- planner 계획을 위와 같이 보존했다. 장비·음성 지원 탐지는 하나의 점검 어댑터에 모았다.
- 사용자 화면 피드백 반영: 카메라도 마이크와 같은 카드·패딩으로 감싸고, 두 열의 카드 높이를 grid stretch로 맞췄다.
- 높이 조정 후 lint·추가 reviewer 리뷰 통과. 사용자 PR 생성 승인으로 커밋·푸시·PR 생성을 진행한다.
- 구현·reviewer 리뷰 완료. must-fix 지적 없음.
- lint·typecheck·전체 테스트 133개·production build 통과.
- production 서버에서 미로그인 prepare 요청이 307 /login으로 이동함을 확인했다.

  장비 어댑터는 mock으로 권한 오류, 입력 감지, 트랙 중단, 재시도 및 늦은 응답 정리를 검증했다.
