# 플랜 보관소 (docs/plans)

이슈 단위 작업의 **구현 계획**을 보존하는 곳. `issue-work` 흐름에서 `planner` 에이전트가 만든
계획을 여기에 저장하고, 해당 이슈의 브랜치/PR에 함께 커밋한다.

## 규칙

- **파일명**: `issue-<NNN>-<슬러그>.md` — 번호는 3자리 zero-pad(정렬용), 슬러그는 kebab-case.
  - 예: `issue-001-scaffolding.md`, `issue-005-auth.md`
- **1 이슈 = 1 플랜 파일.**
- 플랜은 **구현 시작 시점의 의도 스냅샷**이다. 머지 후 사후 수정하지 않는다(기록 보존).
  구현 중 바뀐 점은 파일 하단 "변경 메모"에 덧붙인다.
- 플랜 파일은 **feature 브랜치의 첫 커밋**으로 추가 → PR로 main에 머지(플랜·코드·리뷰가 한 PR에).

## 템플릿

```markdown
# Plan — Issue #<N>: <제목>

- 이슈: #<N>
- 브랜치: <type>/<N>-<슬러그>
- 상태: planning | 구현중 | 완료
- 작성일: <YYYY-MM-DD>

## 목표
<!-- 끝나면 무엇이 되는가 (이슈 완료조건과 연결) -->

## 단계별 계획

## 건드릴 파일 (경로 / 레이어)

## 외부 의존·어댑터 / 스키마 변경

## 리스크 · 열린 질문 · 승인 필요 지점

## 검증 계획

## (구현 후) 변경 메모 / 리뷰 반영
```
